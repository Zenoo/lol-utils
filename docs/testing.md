# Validation and performance

`npm run check` checks TypeScript, lint, formatting, all archived source hashes, regression tests, and a 200-sample recommendation benchmark. Tests cover the entire champion roster for valid rune pages and six distinct purchasable items. Targeted cases cover enemy threat changes, gold, component multiplicity, inventory capacity, mode restrictions, Flash preference, skill gates, user page preservation, timeout behavior, and stopped polling.

`npm run smoke` opens hidden Electron windows, tests encyclopedia navigation, detailed champion/item views, plan generation, settings, and 200 overlay updates with cached icons and explanations, and writes screenshots, app metrics, and overlay memory samples to `artifacts`. It checks that the overlay stays hidden and unfocusable during the test. It does not prove an overlay works in a real match.

The engine benchmark fails if p95 exceeds 50 ms or setup exceeds two seconds. These are generous regression limits for a once-per-second task, not claims about game FPS. The overlay renderer has no animation loop, network requests, or recommendation computation. The main process fetches each recommended item icon once from patch-pinned Data Dragon and sends cached data URLs. Its IPC updates are deduplicated; native focus checks only run while live guidance exists. API requests are serial and bounded to two seconds. Disconnected polling backs off to 15 seconds. Background renderer throttling remains enabled in normal operation; hidden smoke windows render offscreen for screenshot checks.

## Real-client acceptance, still required

The default shop key is P. Unmodified keys use only Windows key-state observation and never register a global hotkey, so League receives the same press. Modified combinations also support Electron registration. Polling checks the chord and Escape every 40 ms without input hooks; foreground/render checks remain capped to roughly four per second. Both notification paths share a press latch so a hold or duplicate event toggles once. Older default Alt+Shift+S settings migrate to P; custom shortcuts survive. Unit coverage checks pass-through registration policy and key-state matching. Real-match delivery, elevation differences and borderless visibility still require acceptance testing.

Skill guidance uses its own small transparent, click-through window, anchored to the bottom-centred skill row rather than the shop panel. The native bridge returns client-area coordinates; geometry is calculated in physical pixels then converted to display DIPs. The app reads `[HUD] GlobalScale` from the running game's installation `Config/game.cfg` every two seconds, with `PersistedSettings.json` as a fallback; no League settings are written. Layout tests exercise all slots, HUD-scale extremes, resized viewports and nonzero monitor origins. Actual alignment across HUD scales and DPI still needs a real-game check; the geometry tests verify transforms rather than the game's rendered pixels.

The desktop smoke checks icon-based numbered progression, rune and skill icons, item pointer tooltips, keyboard-focus skill tooltips, Escape dismissal, and truthful success/pending/error import checkboxes. It also checks that a separate skill marker remains unfocusable and hides after a point is spent. Tooltips escape descriptions and cache at most 64 detail requests; icons retain accessible names and letter fallbacks when offline.

Autocomplete checks cover alphabetical results, keyboard and mouse selection, no-match feedback, valid stored form values, and rejection of unknown roles. Champion, item, and summoner lists are checked for alphabetical ordering, including filtered item results. Runes follow official tree slots. Smoke checks also cover client-driven champion selection, completed-item previews, default Rift deduplication, basic/epic/legendary filters, tagged item names, selected rune slots, and all three overlay explanations fitting in the window. Data storage regressions cover canonical loading, checksums, same-version replacement, removal of outdated files, failed-swap rollback, interrupted-swap recovery, and staging-path boundaries.

1. Run in a practice lobby with the current patch. Verify the lockfile is discovered; select champions, switch rapidly, swap assigned roles, and check the actual rune page, summoner slots, and item set. Test rune-page capacity errors. Personal pages and sets must survive unchanged.
2. Confirm a game patch mismatch and absent version endpoint show a persistent main-app warning while imports and live guidance continue. Check that the overlay contains no patch warning. Restart the League client and app, and confirm reconnection without stale credentials or guidance.
3. Use borderless/windowed mode. Allocate standard and nonstandard skills, including free starting ranks, Udyr stances, Jayce transformations, Yuumi's attachment rank, and Aphelios stat allocations. Hold points, die, reconnect, and end the game. Test changing monitors and DPI; the overlay must follow League and hide on Alt+Tab. Exclusive fullscreen is unsupported.
4. Open/close the shop using P and verify League receives every key press while the companion panel toggles once. Hold P to check repeat suppression; Escape must hide the panel. Mouse shop clicks need an explicit panel toggle. Test a custom shortcut and Alt+Tab. Test the skill marker at both HUD-scale extremes, several resolutions, windowed client borders and mixed-DPI displays; change HUD scale during the match and confirm it updates automatically.
5. Compare no companion, companion idle, companion live with hidden shop panel, and visible shop panel. Record at least 10 minutes per case after a cold launch. Capture game median/p95/p99 frame times, Electron process-tree CPU/RSS/private working set/GPU memory, disk/network traffic, and recommendation latency. Repeat for low-end hardware and a full match. Inspect renderer/texture memory after repeated show/hide and game reconnects.
6. Run a 60-minute soak with purchases, item selling, full inventory, focus changes, client restart, and renderer crash recovery. Check no growing timer/socket/listener count and no steadily increasing memory plateau.

Do not describe live FPS or long-session stability as verified until those measurements have been taken. CI smoke and engine timings cannot substitute for them.
